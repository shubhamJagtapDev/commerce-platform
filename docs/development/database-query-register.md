# Database Query Register

> **Policy:** Required for every use case that reads or writes an application database.

| Use case | Service/owner | Transaction | JPA operation | Equivalent raw SQL | Cardinality/index | Lock/concurrency | Evidence trigger |
|---|---|---|---|---|---|---|---|
| Readiness database probe | Identity Access / platform | Driver-managed read-only probe | Actuator datasource health indicator | `SELECT 1` | One row; no application index | No application lock | Fail readiness when `identity_access` is unavailable |
| Readiness database probe | Catalog / platform | Driver-managed read-only probe | Actuator datasource health indicator | `SELECT 1` | One row; no application index | No application lock | Fail readiness when `catalog` is unavailable |
| Create OIDC login transaction | Identity Access / auth | Read-write; transaction record committed before browser redirect | `AuthTransactionStore.create` via `JdbcTemplate` | `INSERT INTO auth_transaction (...) VALUES (...)` | One row; `auth_transaction` primary key on `state_hash` | State is HMAC-hashed before storage; primary key prevents duplicate creation | Verify raw state/nonce/verifier never appears in PostgreSQL or logs |
| Load OIDC callback transaction | Identity Access / auth | Read-only lookup before callback processing | `AuthTransactionStore.findUsable` via `JdbcTemplate` | `SELECT ... FROM auth_transaction WHERE state_hash = ? AND consumed_at IS NULL AND expires_at > ?` | At most one row; primary key lookup | No lock; a subsequent claim is authoritative | Expired or replayed state maps to the generic authentication problem |
| Atomically claim OIDC state | Identity Access / auth | Read-write; single PostgreSQL statement | `AuthTransactionStore.claim` via `JdbcTemplate` | `UPDATE auth_transaction SET consumed_at = ? WHERE state_hash = ? AND consumed_at IS NULL AND expires_at > ? RETURNING ...` | At most one row; primary key lookup | Atomic compare-and-set prevents concurrent callback/replay consumption | Concurrent callback test proves exactly one claim succeeds |
| Create opaque BFF session | Identity Access / auth | Read-write; session plus authorities commit together | `BffSessionRepository.save`, `BffSessionAuthorityRepository.saveAll` | `INSERT INTO bff_session ...`; `INSERT INTO bff_session_authority ...` | One session; unique `handle_hash`, authority unique `(session_id, authority_code)` | Raw cookie handle and CSRF token are HMAC-verifiers only | Verify raw opaque handle, CSRF token, and token bundle are absent from database |
| Resolve and touch BFF session | Identity Access / auth | Read-write; one session update before the request completes | `BffSessionRepository.findByHandleHash`, entity dirty-check touch, authority query | `SELECT ... WHERE handle_hash = ?`; `UPDATE bff_session SET last_seen_at = ?, idle_expires_at = ?`; `SELECT ... FROM bff_session_authority WHERE session_id = ?` | At most one session via unique hash; supporting lookup/cleanup indexes | Expiry checked before touch; session value is never trusted from a header | Expired/invalid cookies receive no `PrincipalContext` |
| Bounded auth cleanup | Identity Access / auth | Scheduled/manual maintenance transaction (not yet scheduled in Gate 2) | Future cleanup adapter | `DELETE ... WHERE expires_at < ?` and expired-session equivalent | Bounded batches using `auth_transaction_cleanup_idx` and `bff_session_cleanup_idx` | No customer-account cascade or cross-service data | Cleanup batch evidence after Gate 2 runtime verification |
